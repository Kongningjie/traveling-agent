# 旅行动态规划助手

基于 Java 21、Spring Boot 4.1.1、AgentScope Java 2.0.4 与 Vue 3 的旅行助手。现已提供私有旅行会话、需求协商、行程候选及版本界面，当前推进 M4 本地验证与交付；真实模型质量及完整验收尚未完成。需求 v1.0、技术设计 v1.5 已冻结。下方早期阶段说明保留当时验证边界，当前交付状态以本地实施计划和工作日志为准。

## 从一句话开始旅行

登录后点击“开启新旅行”，直接在聊天框描述自己的想法。目的地、日期、同行人数或预算可以尚未确定；前端保留原文，不预填默认人数、无预算上限或没有已订安排。模型调用获准且通过既有门禁后，由后端理解已知信息并针对关键缺项追问；调用关闭或受限时显示真实暂停状态，不生成假回复。

建议按钮仅用于选择，发送后才提交；可以只回答部分问题，也可以在同一个聊天框自由补充。有效追问提交到原问题的版本化回答入口，普通修改仍提交新消息。行程、已记录需求、版本和资料从右上角展开，长期偏好从左下角账号入口管理；新候选始终需要明确接受才生效。

开发模式运行`web`目录的`npm run dev`，源文件变化会更新页面；Docker静态前端需重新构建并更新对应web容器。`npm test`和`npm run build`在web目录验证前端。`TRAVEL_UI_FIXTURE_PORT=4190`环境变量配合`node tests/fixtureServer.mjs`可运行纯回环、合成数据的浏览器夹具，默认端口4189；它不是实际后端，不连接模型、数据库或供应商，不能将其结果记为模型规划质量。

## 工程结构

| 目录 | 职责 | 依赖方向 |
| --- | --- | --- |
| api | HTTP 接口、请求响应对象、Web 安全配置 | application |
| application | 用例编排、应用服务、对外端口 | domain |
| domain | 业务模型、状态转换、核心规则 | 不依赖其他项目模块和框架 |
| agent | Harness 适配、Agent 角色及上下文 | application、domain |
| infrastructure | 持久化、Redis、外部工具及执行基础设施 | application、domain |
| bootstrap | 唯一后端启动入口与依赖装配 | 其他五个后端模块 |
| web | Vue 3＋TypeScript 前端 | HTTP 接口；独立于 Maven |
| docs | 需求、设计、计划、规范和日志 | 见[文档导航](docs/README.md) |

Controller 和 Agent 工具通过应用服务或端口协作，不能直接访问任意 Mapper。业务领域在各层内部按包组织，不继续拆成大量 Maven 模块。

## 本地准备

- JDK 21、Node.js 24 LTS（当前验证版本 24.14.0）、npm。
- Maven Wrapper 固定 Maven 3.9.11，首次构建需要联网下载依赖。
- Docker Desktop / Compose 用于 PostgreSQL、Redis 和完整容器联调。
- 当前骨架不需要任何模型、地图或检索服务密钥，不会发起这些服务调用。

## 无外部服务的快速验证

在项目根目录执行：

```powershell
.\mvnw.cmd --batch-mode --no-transfer-progress verify
java -jar bootstrap/target/traveling-agent.jar --spring.profiles.active=smoke
```

另开终端启动前端：

```powershell
cd web
npm ci
npm run dev
```

访问 `http://127.0.0.1:5173`。开发代理将 `/api` 转到 `127.0.0.1:8080`。后端提供：

- `GET /actuator/health`：进程健康状态。
- `GET /api/v1/system/info`：骨架装配状态，不包含凭证或用户数据。

`smoke` 禁用数据库、Flyway、Redis 和服务端会话自动配置，仅验证 Web 层、应用服务与 Harness 适配类装配。它不代表数据库、登录、真实模型、工具调用或恢复机制已验收。当前未提供可登录账号，其余接口默认拒绝访问，CSRF 防护保留。

Windows 下重新打包前先停止运行中的同一 JAR，避免文件占用使 Boot repackage 失败。

## 本地 Docker Compose

先启动 Docker 引擎，复制配置并修改两个示例密码：

```powershell
Copy-Item .env.example .env
```

只启动中间件，供 IDE 调试：

```powershell
docker compose up -d --wait postgres redis
```

在 IDE 中启动 `TravelingAgentApplication`，启用 `local` profile，并设置与 `.env` 一致的 `POSTGRES_PASSWORD`、`REDIS_PASSWORD` 环境变量；其他连接参数默认指向本机。**Spring Boot 不会自动读取 Compose 的 `.env` 文件**。如修改数据库名、端口或用户，也需同步设置对应环境变量。启动会执行 Flyway；V1 创建应用 schema，V2 建立请求预算和计量表；旅行及账号业务表在后续迭代追加。

完整容器方式（先在宿主机生成后端 JAR）：

```powershell
.\mvnw.cmd --batch-mode --no-transfer-progress verify
docker compose --profile app up -d --build --wait
docker compose --profile app ps
```

访问 `http://127.0.0.1:8088`，Nginx 同源转发 API。PostgreSQL、Redis、后端和前端均有健康检查，web 在后端健康后启动；`--wait` 等待就绪。Nginx 仅转发健康检查，其他 `/actuator/` 路径返回 404。

```powershell
docker compose --profile app logs --tail 100 backend
docker compose --profile app down
```

`down` 保留命名卷。PostgreSQL 卷保存业务状态，Redis 卷保存会话数据；`agent-files` 预留给附件及确需保留的框架文件，不承担文本会话、检查点和 JSON 产物的权威存储。数据库和文件的备份恢复流程在后续阶段验证。

镜像标签写在 Compose / Dockerfile 中；JRE 当前使用 Java 21 系列标签，本轮实际解析的镜像 digest 已记录在 Docker 验证日志中。配置仅供本地开发，云端 HTTPS、密钥托管及发布方案另行落实。

## 真实本地基础设施验证

```powershell
.\scripts\verify-local.ps1
.\scripts\verify-persistence.ps1
```

第一个脚本临时读取 `.env` 的连接配置，验证 Flyway、PostgreSQL JSONB 与事务回滚、Redis Session 以及 MyBatis 请求计量、并发预占和未知用量，执行后恢复当前进程环境变量。普通 Maven verify 默认跳过需显式启用的容器测试；实际测试数以当次报告为准。

第二个脚本会重新创建本项目四个容器，验证 PostgreSQL 和 Redis 数据在命名卷中保留，随后清理本轮随机探针，不删除卷或业务数据。运行时会短暂中断本地访问。它验证基础设施持久化，不代表应用阶段恢复和登录业务已经实现。

## 开发与代理约束

模型调用准入默认关闭。计量代码不创建 SDK，也不会发送真实请求。`config/free-quota.example.yml` 仅是过期、零额度且未确认停用的安全示例；真实非凭证快照可放入被忽略的 `config/free-quota.local.yml`，从项目根目录启动时可选加载。不要覆盖已有本地文件，不要将 Key 写入快照。

准入检查精确角色、型号、地域、接口、实际免费额度到期时间、余额和供应商停用保护，再在短事务中预占原运行预算。按用户要求，历史 `valid-until` 仅兼容旧配置，不再因本地快照时效自动拒绝；不伪造新的核实时间，不清除未知用量。记录已知 Token／耗时，未知或未结束请求保留保守预占；重建仓储或重复建账不重置预算。单实例实际请求最多 4 个；许可提供的超时已接入真实 SDK，不能仅因超时或浏览器断开就提前释放仍在途请求。

本地计量只覆盖本项目，不是账户实时余额，也不保证其他程序不会消耗额度。供应商保护、实际端点、权限及用量回调要在 Harness 接线时实测；当前尚未实现完整运行状态机、活跃区间驱动和故障补偿。不得在未完成这些对应门槛时将参数存在误称为全套运行恢复已实现。

开始工作前阅读根目录 [AGENTS.md](AGENTS.md)。开发阶段必须按计划串行执行，测试及推送前 Review 通过、日志补齐并核对远程 main 包含交付提交后，才可进入下一阶段。所有真实密钥禁止进入对话、日志或 Git；.env 永不提交。

用户指定 docs/ 全部只保留在本地，因此仓库页面中的 docs 链接仅在具备本地资料的工作区可用。编码、环境、技术栈和流程详见本地 [standards](docs/standards/README.md)。新克隆环境若缺少冻结方案或阶段资料，需先由用户在本机补齐；不能根据 README 摘要擅自开始实现。

## 离线 SSE 与执行资源探针

使用 smoke profile 启动后，可访问 `/api/v1/system/probe-events`：固定发送 started 和 completed 两个事件，五秒超时、最多两条连接；断开连接不会取消固定后台任务。该接口只验证 MVC SSE 接线，不接收旅行需求，不访问模型或工具，不支持历史事件补读；非 smoke 环境不装配且默认拒绝访问。

执行资源端口提供全局活跃运行与每运行调查分支限制，当前配置分别为 2 和 2。分支使用独立虚拟线程资源，父流程以 CompletionStage 组合结果；真实模型请求仍单独使用全局 4 个请求槽。关闭运行范围后，尚未退出的分支继续占用容量。资源实现不替代 PostgreSQL 阶段调度、租约、预算及业务取消；这些按后续阶段实施。

DEV-0008 已增加受门禁保护的模型 SSE 传输，运行适配器采用流式 SDK；本地可控 HTTP 响应覆盖真实 SDK／Harness 的工具与结构化输出流程。终帧累计用量在响应关闭后结算，取消、截断或用量缺失仍保留 UNKNOWN；单行／事件、总流及帧数均有限制，不缓存完整生成结果。

按用户要求，本阶段仅本地验证，三个型号的真实流式兼容性仍未运行，不将本地替身结论写为供应商验证通过。M0 真实验证门槛保留，未经针对当前范围的明确允许，不执行真实调用或额度查询，不反复询问余额。

## 后端账号认证

local profile 提供 `/api/v1/auth/csrf`、`register`、`login`、`me`、`logout`。先 GET csrf，使用同一会话 Cookie 和返回的请求头提交注册／登录；登录后重新取得 CSRF 再提交后续写请求。登录名 3～32 位字母数字下划线、大小写不敏感；密码 8～64 个字符且 UTF-8 最多 72 字节。密码不放命令行或日志。

PostgreSQL 保存账号及 BCrypt 哈希，Redis 保存不含密码的会话及临时认证限流计数。登录轮换会话 ID／CSRF，退出使服务端会话失效；Cookie HttpOnly、SameSite=Lax，只有本地 HTTP 配置关闭 Secure。可用 `scripts/verify-local.ps1 -Scope Identity` 验证本地账号流程，不调用外部服务。登录和注册限流参数位于 `travel.identity`，默认每地址登录 30 次／分钟、每账号 10 次／分钟、注册 10 次／分钟。

本阶段仅交付后端认证，前端登录页面及旅行资源接口后续接入。smoke 不提供真实登录；已有 app 容器未自动重建，不代表运行中镜像已更新。

## 必要产物与本地恢复

普通工具响应、网页文本、会话、检查点和JSON阶段产物继续以PostgreSQL为权威存储。独立需展示的文本／JSON产物保留原始UTF-8字节及哈希；图片、PDF和实际产生的必要框架文件才存文件卷。框架文件不可下载，不增加附件上传业务。`GET /api/v1/artifacts/{id}`要求所属用户会话，限10MiB、限定类型、附件下载、禁止缓存，读取时核对大小和SHA256；缺失或损坏明确失败。

宿主机文件根默认`.runtime/artifacts`，Compose后端为`/var/lib/traveling-agent/artifacts`，与可丢弃的`.runtime/harness`分离。文件落盘及索引登记与孤儿回收使用PostgreSQL事务锁协作；仅回收24小时之前的无引用受管文件，不自动删除未知文件或有效附件。回收仅为受信维护应用入口，无HTTP／Agent工具入口。

停止所有宿主机执行器后，可用PowerShell 7运行`./scripts/backup-local.ps1 -Action Backup -Directory .runtime/backups/manual-001 -Quiesced`。脚本短暂停止运行中的容器后端，备份数据库与必要文件，随后恢复后端运行状态；目标必须为受管根`.runtime/backups`的直接新子目录，成功备份30天到期，未完成备份24小时到期。使用其他受限根须传`-BackupRoot`并同步配置服务端清理根。宿主机文件模式另传`-FilesDirectory .runtime/artifacts`。备份含私有数据，应保存在受限本地目录；不会包含`.env`或Redis登录会话，恢复后重新登录。

运行`./scripts/backup-local.ps1 -Action Verify -Directory .runtime/backups/manual-001`，会在随机临时数据库和临时卷中实际恢复，先逐表比对备份内容指纹，再重放独立最新删除清单，移除恢复文件中的已删原件，核对剩余文件引用的大小与哈希，结束清理临时资源；不会覆盖当前源库或原文件卷。该脚本是本地恢复演练，云端备份、加密存放、RPO/RTO及正式切换恢复流程留待部署阶段。`./scripts/verify-local.ps1 -Scope Artifact`覆盖本地存储、隔离、回收锁及备份恢复，不调用真实外部服务。

## 固定场景本地基线

PowerShell 7 执行 `./scripts/evaluate-local.ps1`：默认仅运行 8 个开发场景；显式使用 `-IncludeHoldout -RepeatRepresentatives` 时包含 4 个留出场景，并将 E01、E03、E06、E11 各运行到 3 次，共 20 条本地契约记录。场景、合成种子与程序裁判位于 `bootstrap/src/test/resources/evaluation/v1`，原始 UTF-8／LF 字节经过 SHA256 校验；变动会拒绝执行，不自动更新预期。

该入口使用真实本机 PostgreSQL 和受控本地提取／压缩替身，强制关闭真实供应商调用。测试只清理本轮随机用户；会短暂停止正在运行的容器后端以避免 Worker 争抢，结束恢复。JSON／Markdown 报告保存在被忽略的 `.runtime/evaluations/contract-*`，包含分区、次数、检查失败码、耗时、数据指纹和源码指纹，不保存控制台或 Docker 日志。不要将这些本地报告强制加入 Git。

这不是完整模型 E2E 或质量评分：三城市用例当前只探测结构，局部修改只探测 Patch 契约；自然语言提取、真实规划和独立质量审查没有执行。真实模型、真实工具逐场景标为 `NOT_RUN`，未运行的 Token／延迟不补零。真实模型评测端口和独立裁判已定义，但实际模型执行适配、稳定后的重复试验、全量／局部质量对照及浏览器演示仍待验收；本地通过不表示 DEV-0024／M4 全部完成。以后真实调用仍须取得用户对当次范围的明确授权，不能因模型 Key 已配置或运行此脚本而启用。

依赖与配置以父 POM、各模块 POM、Wrapper、`web/package-lock.json` 及 `config/` 受管示例为准；报告记录当次源码指纹，运行中的未提交版本不能只凭父提交号复现。详细覆盖矩阵及后续验收步骤见本地 [评测与验收规范](docs/standards/评测与验收规范.md)。

## 本地故障与资源验收

`./scripts/verify-local.ps1 -Scope Fault`运行输入及阶段事务硬退出、失联租约、取消迟到结果、重复提交、并发接受、SSE断线与会话失效、偏好删除、上下文及附件恢复、模型超时和限流、免费额度暂停等确定性实验。测试只使用本地PostgreSQL／Redis、回环HTTP和受控模型替身；不调用真实供应商。测试脚本会暂时停止运行中的容器后端，避免其Worker争抢测试任务，结束后恢复原运行状态；其他宿主机执行器应先停止。

`./scripts/verify-faults.ps1 -IncludeContainerFaults`额外执行后端SIGKILL重启、PostgreSQL／Redis重启和随机持久化探针核对，会短暂中断服务并保留命名卷。`-ContainersOnly`可只补做容器实验，避免重复已经通过的测试。容器健康探针与精确事务边界的JVM硬退出测试分别记录结果；本地故障通过不代表云端可用性或真实模型质量验收完成。脚本不保存控制台日志。真实免费额度耗尽经HTTP或SSE到达时，类型化拒绝会直接进入PAUSED_QUOTA，UNKNOWN用量仍保留原预占，不自动重发、付费或更换型号。


### 对话意图与本地验证

自由文本先保存至独立聊天，再由协调角色一次理解“交流咨询／规划协作／明确操作／待澄清”及需求字段。明确规划后一个聊天关联一个旅行任务，历史任务也可关联；咨询不创建占位旅行或修改已有需求。识别期间原规划可以计算，但候选展示与接受受数据库屏障保护；失败输入保留原文，可显式重试或撤回。聊天记录、助手回复、确认卡和租约均存PostgreSQL，使用既有Worker与调用门禁。

自然语言中的接受候选、恢复版本及保存／删除长期偏好需点击精确确认卡；明确停止可直接处理，文字授权仍需在问题卡片选择具体范围。咨询回复基于可用上下文，不接入即时检索工具，不声称已核实实时天气或票价。真实外部调用默认关闭，因此配置密钥并不表示聊天模型已启用；关闭时可靠保存输入并显示明确原因，不用本地规则伪装模型回复。

本地验收使用 `.\scripts\verify-local.ps1 -Scope Dialogue`（仅本机PostgreSQL／Redis与显式模型替身），前端运行 `npm test` 与 `npm run build`。40条人工标注意图语料位于 `bootstrap/src/test/resources/dialogue/intent-cases.json`，分30开发／10留出；语料契约与替身测试不代表真实模型准确率，真实质量评测尚未运行。

## 二期作业与调用归属

DEV-0026将自由输入接入持久化作业：聊天可独立存在，每条输入使用稳定operation预算，失败重试沿用原预算。旅行阶段继续使用原run预算；实际模型／工具请求只登记一次调用归属。初始输入上限8次模型、12次工具、5分钟主动执行，用户每日上限100次模型、200次工具、50次解析，按Asia/Shanghai预占日期结算；UNKNOWN不返还次数或清除免费门禁。

`travel.jobs`可配置`model-limit`、`tool-limit`、`active-seconds`、`daily-models`、`daily-tools`、`daily-parses`。输入创建时保存限制快照，修改配置不为旧输入补发预算。文件上传与隔离解析已接入同一JobHandler；文档分析／记忆维护仍待后续阶段实现，无处理器的类型保持排队。

作业领取、失联恢复、依赖和用户等待、取消、水位及token围栏共用现有Worker；解析使用独立单槽，取消后物理执行退出才释放容量。HTTP响应包含服务端生成的X-Request-ID和X-Trace-ID，PG保存输入、作业、阶段、调用的关联与固定分类问题记录，不保存诊断正文或凭据。诊断运营查询界面在后续阶段实现。

`./scripts/verify-local.ps1 -Scope Job`执行本机PG／Redis和受影响回归，外部调用强制关闭；可通过`-TestMethod`选择JobIntegrationTest方法。不执行完整质量验收、不保存完整控制台日志。已有容器镜像不会随源码自动重建。


## 二期统一会话与基础安全门禁

DEV-0027使聊天与旅行调用共用PG会话上下文：权威需求、当前版本、已确认偏好和本轮请求属于保护区，近期用户／助手消息保持原角色和完整正文，审核不读取规划者的对话历史。替换了4轮、单侧300字符和8192字符丢弃上下文回退。应用按角色预算选择近期完整轮次，并在最终HTTP正文（包括系统说明、工具schema和结构化输出协议）再次核算；超出保护预算则暂停，不截断关键约束。

复用Harness 2.0.4的ConversationCompactor，由应用显式驱动一次压缩，不同时启用原生自动Flush或第二套摘要循环。PG保存摘要引用、覆盖前缀、依赖指纹和尝试围栏；只有同一有效尝试或成功提交来源可以复用，取消／失败摘要不能成为下一轮记忆。当前消息装载窗口最多200条输入，近期目标约4000保守估算单位、最多24条消息，实际随角色和保护区大小收缩；更早原文仍在PG，未装载时提示指代不明应澄清，不声称全文永久在模型上下文。跨窗口原文按需检索和文件记忆在后续阶段实现。

偏好删除／版本变化后旧摘要和旧偏好版本历史不再注入，模型结果提交时再次检查。摘要失败记录固定问题编号并回退到有效摘要及近期完整原文；没有有效摘要时明确历史不完整。上下文超限只在传输可确认零用量时允许一次同预算恢复，缺失用量继续UNKNOWN且不自动重发。这一供应商错误分类仅经本地受控HTTP验证，不代表真实型号协议已验收。

基础SafetyGate检查输入、上下文、摘要、工具参数／结果和最终模型正文，拒绝脚本／危险链接和已配置凭据的原值泄露；检查异常失败关闭，诊断只存固定原因、策略版本及问题ID。应用调查和Agent工具共用边界；SDK吞掉工具异常时仍阻止后续调用及最终提交。该确定性策略不是完整语义内容审核，也不承诺识别全部提示注入，公开上线安全验收仍待后续完成。页面保持只显示进度及检查后的最终回复，没有开放原始Token直通。明确停止指令在服务端直接完成，不排队等待模型；含糊／否定表达继续走原澄清流程。

`./scripts/verify-local.ps1 -Scope Session`覆盖本机PG／Redis、50轮上下文、服务重建、偏好删除、取消、工具schema预算与安全拒绝等本地回归；工具边界补充用例为TravelToolContractTest。真实供应商调用仍默认关闭，现有Docker后端镜像未自动重建。附件上传、隔离解析、引用检索及文件工作记忆仍待DEV-0028／0029，完整质量验收继续按既定安排延期。


## 二期附件上传与隔离解析

DEV-0028提供聊天内PDF文本层、DOCX、UTF-8 TXT／Markdown上传、状态、原件下载、显式停止／重试／删除。文件可以作为新聊天的第一项资料，不创建旅行占位。此阶段只保存和提取，文件检索／引用和优化分析分别在后续DEV-0029／0031接入，不能将附件READY理解为已经完成旅行分析。

原件默认位于`.runtime/documents`，Compose以独立持久化目录挂载；PG的uploaded_document保存不可变原件ID、归属、哈希和报告／页段全文。文件名仅展示，服务器生成键；10MiB、100页、20万字符、50MiB展开量、60秒墙钟为初始上限。聊天10份、用户200MiB原件／100万字符，待处理文本预占，完成后按实际字符结算。`.env.example`列出DOCUMENT_MAX_*配置，首轮只允许收紧当前安全协议上限；调高需相应Review、测试及必要迁移。磁盘85%停止接纳、80%恢复，读取和删除仍可用。

先在专用终端执行：

```powershell
.\scripts\document-parser.ps1 -Action Build
.\scripts\document-parser.ps1 -Action Run
```

Build打包并构建固定解析镜像，将镜像sha256和缺失的随机runner认证配置写入本地.env，不打印秘密。Run使用本机Docker权限，默认只监听127.0.0.1:8766；IDEA后端需在环境中加载同一DOCUMENT_PARSER_SECRET。不要把该值粘贴到对话或命令行。Compose后端通过host.docker.internal访问宿主机，仅此受限技术进程持Docker权限，后端不挂Docker socket。其他平台如需更改监听，必须先限制宿主机防火墙，不能直接公开runner端口。

每作业容器固定镜像、无网络、只读根、原件只读挂载、UID65532、cap-drop ALL、no-new-privileges、1CPU／512MiB／64PID及64MiB tmpfs。HMAC绑定启动挑战、路径和完整请求，检查时间及一次性nonce；重启拒绝旧签名并在接受工作前清理专用标签的旧解析容器。runner不连接PG、不领取业务作业、不调用模型。不可用时暂停，绝不退回Web进程解析。扫描／加密／损坏／超限文件没有READY；复杂表格、版式及未做OCR的限制在页面明确展示。

删除立即撤销读取、清除PG正文及原文件名、取消该附件的在途资格；每分钟尝试清理原件，物理失败保留墓碑和容量并重试。依赖引用、框架工作记忆、摘要和历史派生回复同时撤销；未接受候选失效，已确认需求及已接受行程保留。删除单份来源不会取消其他附件的解析。当前使用v3受管备份，含documents.tar及明确到期时间；自定义原件根须传`-DocumentsDirectory`。v1/v2备份不能直接走当前恢复入口，应在离线维护环境迁移验证，不开放旧资料。

附件本地回归使用`./scripts/verify-local.ps1 -Scope Document`。真实容器测试另需本机Docker及DOCUMENT_CONTAINER_TESTS=true、DOCUMENT_PARSER_IMAGE为已构建镜像sha256，运行DocumentContainerTest；该测试只用合成文件和本地HTTP，不调用任何真实业务供应商。verify-persistence.ps1还核对原件目录在容器重建后保留。验证过程中不归档控制台／Docker日志。

## 二期资料检索、引用与工作文件

READY附件提供“检索原文”，支持中文等字面关键词，单次最多5个页段；片段包含原件ID、哈希、解析器版本、真实页段及UTF-16字符范围。无命中、部分读取和提取限制明确显示，不把用户计划当官方证据。引用预览只展示纯文本。成功回复下可按需查看实际读取或工作文件所依赖的材料片段，不使用模型自报引用作为依据。

有原领取身份的协调角色可使用ListDocuments、SearchDocument、ReadDocumentSection、ReadConversationSource及受限read_file。默认只装入目录，单段最多4000字符；历史检索最多5条及12000字符，只查当前聊天、本轮之前、当前偏好版本。所有Agent工具读取计入所属输入的原工具预算，失败不自动重试；不会因本地资料可读而打开真实模型或外部工具开关。调查/规划角色扩展由后续策略阶段处理。

复用Harness 2.0.4原生ToolResultEvictionMiddleware：大于6000字符的可卸载结果先保存PG，再替换为160字符头尾预览和/work逻辑引用。read_file仅分页读取该逻辑键，不访问OS路径；卸载失败由发送守卫失败关闭，不能悄悄保留全文继续发送。工作文件和引用的正文、哈希、归属、偏好/资料水位及尝试来源全部在PG；无需宿主文本文件缓存，新实例可恢复成功尝试的工作记忆，取消或失败尝试不可恢复。默认记忆Flush、后台调度、通用Shell/文件工具继续关闭，不把讨论写成长期偏好。

每聊天引用和工作文件上限200条、累计200万字符（包含本次写入）；目录最多列最近10个有效工作文件，达到容量时明确拒绝，不扩大预算。删除源附件会立即撤销该聊天引用/工作文件，清除相关摘要，保守遮蔽首次资料读取起的助手回复链，并通过原JobStore取消依赖旧资料的活跃输入；用户原消息及已确认业务需求保留。原件物理清理仍沿用上一阶段协议，完整备份删除标记重放在后续生命周期阶段。

本地定向验证：`./scripts/verify-local.ps1 -Scope Source`。本阶段没有新开网页导入或真实供应商联调，原计划分析/建议采纳仍待后续阶段。

## 二期受控策略与执行追踪

协调角色返回版本化策略：调查、复用或澄清。Java验证查询与工具白名单、依赖拓扑、需求/偏好版本；一次最多12项调查，同一运行最多2分支并发。阶段与后继全部由原PostgreSQL/Outbox调度，至多补查一轮，不能递归委派或跳过规划后的确定性校验、独立审核及用户接受。部分工具失败保留UNKNOWN，免费门禁拒绝仍暂停。

分支交接包含服务器生成的用户/任务/运行、需求与偏好版本、角色、输出schema、工具范围及来源引用；提交时重新验证偏好与证据有效性。旧顺序查询检查点继续兼容，新Harness策略必须显式返回新协议。缺少关键信息生成可自由回答的问题卡，不回退为创建旅行大表单。

PG执行轨迹关联协调、委派、上下文、实际压缩、资料读取、工具、校验和提交；只保存固定状态、ID、版本、来源哈希及原账本计量汇总，不保存提示词、响应、异常原文或内部思维链。诊断子节点独立于业务attempt，不取得提交权。进程崩溃留下的未结束节点表示中断事实，不冒充完成；诊断查询和问题处理界面随后续阶段交付。

本地完整关联回归使用`./scripts/verify-local.ps1 -Scope Strategy`，追踪接缝回归用`-Scope Trace`。默认真实外部服务仍关闭；本地协议验收不等于真实策略质量通过，完整质量验收继续后置。

## 二期原计划分析与建议采纳

上传并解析为READY后，可点击“解释计划”“检查问题”或“优化建议”，也可以在聊天中自由描述。分析默认是只读交流，不创建旅行；文件中的已订、打算、可选和未知与系统确认的固定安排分开，用户文件不能作为官方核实。

结构化建议显示连续原文、问题/原因、建议、影响、证据状态和待确认项；引用必须来自本次协调尝试实际读取的片段，可以按需查看精确页段。每次最多8项、每聊天最多200项，当前面板显示最近40项。用户逐项拒绝，或查看具体字段后再次确认采纳，也可在原字段范围自定义；确认结果未知时保留原建议ID和正文供显式重试。

采纳只登记新规划/变更请求，不会把候选直接设为生效；仍经原需求版本、Java依赖范围/Patch、全程校验、独立审核及用户接受。第一项采纳推进任务代次，旧版本上的其他建议保守标为过期，不能盲目连续采纳；重新分析会按最新业务重新合并。来源删除或偏好变更立即清除派生建议；已确认业务需求按原规则保留。建议不允许通过固定安排/锁定字段取消预订或解除锁定，需在聊天/明确问题中进一步澄清。存在待确认项或仅解释、没有可执行字段时不会创建空旅行。

本地阶段回归用`./scripts/verify-local.ps1 -Scope Advice`；产物提交相关回归用`-Scope AdviceCommit`。网页UI合成夹具可设置TRAVEL_UI_FIXTURE_ADVICE=true后运行web/tests/fixtureServer.mjs；只监听回环地址，所有结果为合成，不连接真实模型。默认真实外部调用仍关闭，真实语义质量/一期M4及二期完整验收继续后置。


## 二期反馈、问题管理与受限维护

回复、附件、建议和运行状态可主动“报告问题”，默认仅发送目标ID、分类和用户填写的1000字以内说明，不上传整段会话、原文件、截图、浏览器DOM或原始异常。单用户每小时20条；相同输入ID可原样重试，成功提交PG后才显示真实问题编号。“反馈与问题记录”仅显示本人最近20条，历史摘要可通过分页接口读取。

维护权限默认无人持有，由受控数据库管理操作维护`maintenance_grant`，不提供自注册或HTTP授权接口。普通维护授权只能查看固定问题元数据及至多200步的链路；读取反馈正文还须额外`sensitive`授权并显式操作。授权变更和维护读取、本人正文读取均写审计。维护入口在反馈面板中按实时权限显示；复制用户的问题编号可定位其原始trace/span，不以用户填写的文本猜测步骤。运行状态反馈绑定运行根节点，可继续展开其阶段和Agent子链；早期没有追踪数据的回复允许反馈，但不编造原始链路。

自动诊断按相同组件/固定错误码每小时聚合，不代表根因已确定。主动质量反馈逐条建单，不因分类相同批量关闭，维护者可显式标记重复。正常取消、来源失效和部分额度/调用限制事件按INFO处理，不出现在默认故障列表。问题依次分类、处理、修复和验证；修复必须填版本及回归用例，验证还须明确确认通过；运行重试不会自动改变问题状态。重复问题可关联目标组，仍支持重新打开。

诊断表及索引按PG实际分配空间设置初始1GiB阈值，达到上限丢弃新诊断，不影响业务审计。分配空间包含待回收页；到阈值后需维护者释放数据库分配空间，单纯逻辑删除不保证立即恢复写入，完整清理与回收在DEV-0033验证。浏览器固定分类诊断每分钟最多1次、每页面最多10次，服务器每用户每小时10条；不接受任意错误正文。反馈存储失败只显示“未确认保存”，不会用随机编号冒充已落库；PG故障降级仅保存128条固定ID，周期每次最多补写8条、每条最多尝试3次，并提供失败/丢弃计数。降级内存队列可能随重启丢失，不承担业务恢复。诊断30天清理、用户删除及备份删除标记重放随DEV-0033生命周期阶段交付，当前阶段不宣称已完成全部保留策略。

本阶段验证：`./scripts/verify-local.ps1 -Scope Support`；只连接本地PostgreSQL/Redis和回环HTTP，不调用真实业务供应商，也不授予任何实际用户维护权限。


## 生命周期、容量与安全恢复（DEV-0033）

聊天顶部可预览并确认删除整段聊天及唯一关联旅行（含版本、附件、派生记忆）；附件有单来源删除确认。共享长期偏好不随旅行删除。确认使用当前对象集摘要，预览后范围变化返回冲突，用户重新查看；网络结果未知只允许原幂等键显式重试。

PG保存权威墓碑及清理索引；`.runtime/lifecycle`独立保存只有UUID、范围、时间和链式哈希的最新删除清单。它不进入业务备份，不能随旧PG一起回退、清空或替换。条目已完整落盘而头未更新时，应用先校验并补封；只读备份/回滚脚本会拒绝未封存条目，须先运行当前应用恢复。删除先封存清单再提交PG；清单和PG水位不一致时关闭私有资料和Worker领取，恢复重放完成才开放。清单缺失/回退/损坏会拒绝启动/恢复。IDEA的Working directory请设项目根，或者将`TRAVEL_DELETION_ROOT`设为该目录的绝对路径；Docker已映射相同目录。

每分钟有界清理，文件删除失败保留引用和容量，退避重试并记录固定问题；维护权限可读`GET /api/v1/lifecycle/health`查看待清理、失败、24小时逾期及诊断丢弃数。正常目标是在线原件/派生副本24小时内清理；存储持续故障会产生逾期，不虚称已清理。诊断30天回收，逻辑容量按保守行负载统计，磁盘另以85%停止接纳/80%恢复；技术墓碑独立于诊断采样长期保留（超过备份期限）。受管备份最长30天自动淘汰，其他目录/未知备份不会被擅自清除，维护者须自行移入受管范围或处置。

同一Worker内每用户最多一个模型工作（聊天与旅行共享）及一个解析，用户轮转、同聊天FIFO；全局沿用两模型工作/四模型请求/一解析槽。取消只撤销逻辑资格，物理工作未退出前不释放用户槽。每用户最多十个待处理请求，重试也受限制，内部投影不重复计数。容量拒绝不阻断读取、停止、删除；数据库验证脚本互斥，避免两个进程相互恢复容器后端。

回滚使用`./scripts/rollback-local.ps1 -Image sha256:<已验证本机镜像摘要>`，会短暂重建后端；只允许生命周期协议1镜像，拒绝不支持最新删除清单的DEV-0032及更旧镜像。数据库迁移和删除清单不回退；失败保持维护状态。备份恢复脚本仅演练临时库/卷，不做生产源库切换；正式云端切换、异机加密保管及RPO/RTO仍需部署验收。本地协议、故障和恢复验证不代表一期M4或二期真实模型质量验收完成。

## 二期本地集成与验收准备（DEV-0034）

`bootstrap/src/test/resources/evaluation/v2`保存24个合成会话场景，16开发／8留出，四类各6例、每类2例留出。2026-10-20用户确认标注；`manual-oracle.json`中的确认状态只批准判定标准，各次实际人工结果仍为`UNREVIEWED`。输入、程序裁判、人工标注分别封存，`suite-lock.json`和加载器固定总SHA256。留出结构检查不等于留出质量运行，不依据留出修改生产Prompt。

P05是“停止当前回复”，撤销执行资格并拒绝迟到提交；P06是被动断连、重连和同消息重放，后端继续持久化，重连沿用原inputId。关闭页面不会自动取消旅行。运行中的消息操作显示“停止本次回复”；暂停或澄清时仍显示“撤回这条输入”。

本地回归使用`./scripts/verify-local.ps1 -Scope PhaseTwo`，只连接本机PG／Redis及可控替身。`-Scope Migration`在本次新建的唯一临时数据库验证一期V18升级，不降级或删除源库。全量阶段脚本不需每次编辑都重跑；定向方法选择和阶段验收遵循AGENTS.md。

固定性能基准使用`./scripts/verify-phase2-performance.ps1`。它创建独立随机Compose项目及新卷，四服务合计4CPU／8GiB，核验SSD，使用真实登录／PG／Redis／Worker，5用户各4个持久化旅行任务，理解替身固定一秒。收件、状态、停止分别计算nearest-rank P95，不把模型耗时计作接口延迟。运行后只移除该随机项目和解包临时目录；结构化指标、镜像／代码字节指纹保留在被忽略的`.runtime/evaluations`，不保存整份控制台日志。需要Docker至少4CPU／8GiB及本地已有web镜像；前端更新后先执行`npm run build`并构建web镜像。

浏览器专项可用同脚本`-UiOnly`，额外发布`127.0.0.1:4195`。它使用专用测试主进程与服务器内存中的合成身份，实际业务接口仍经过安全链；不等同于正常浏览器登录验收。性能模式只有internal网络；UI模式额外增加关闭出口伪装的入口网络。两者均关闭真实业务调用、不载入供应商密钥。测试专用直接解析器仅供受控合成文件的UI联通，不能替代`DocumentContainerTest`独立无网络容器验证。结束时停止脚本输出项目中的backend，脚本回收该项目；不要清理现有业务卷。

真实会话评测提供显式装配API，默认测试和生产均不自动启动：`SessionEvaluationExecutor`分离执行与Judge；`HttpSessionEvaluationDriver`走实际本机HTTP注册、登录、消息、上传、删除及停止接口；`JdbcSessionEvaluationEvidence`从同一PG只读快照取得各预算分支实际计量及状态。原文、Cookie和认证数据不进入报告。删除聊天前保留匿名用量，不能将删除后的清零查询当零消耗。未授权、计量缺失／UNKNOWN、型号不匹配、重启驱动未配置均不能登记通过。

DEV-0035装配时仍须绑定封存文件夹具、独立程序判定器、故障前置及实际本地重启回调；执行器不能读取Oracle，程序Judge不能调用模型自评。P04摘要失败、P17预算耗尽、P18子Agent失败、P24费用未知需受控环境注入，P22还需实际反馈提交，不能靠用户说“如果失败”冒充故障已发生。任何前置不满足都保留未运行。P24若核实为调用前拒绝，可记录零实际调用，但必须有独立门禁审计证明、全部程序检查和人工记录；这种任务合规证据不代表模型生成质量。

`EvaluationRunner.runModels`支持显式1～3次独立会话，暂停后不继续后续真实调用；`PhaseTwoQualityGate`核对冻结指纹、8留出×3、实际计量及24份人工证据，再判断至少22次语义达标及零重大违规。本地替身报告、未配置检查或缺少人工记录不能通过该门槛。只有本地工程证据已齐全；一期M4和二期完整真实质量仍待DEV-0035，不代表可以公开上线。

### 独立本地 Langfuse（LF-1）

执行 `./scripts/langfuse-local.ps1 -Action Up` 初始化本地随机认证并启动独立评测栈；入口为 `http://127.0.0.1:3100`。LF-3治理未完成时入口返回503，不开放平台数据。登录信息仅在本机 `.env` 的 `LF_USER_EMAIL`、`LF_USER_PASSWORD` 查看，不提交或发送。`-Action Status` 查看状态；旧的`Verify`/`VerifyMetadata`写入探针在入口未核验时拒绝执行，不绕过内部Web端口。

镜像按摘要固定，栈使用独立内部网络、数据库与卷，不复用旅行助手会话空间。当前只提供合成接线，未启用业务采集；元数据、评分、统一30天清理及 Prompt 对比分后续专项接入。项目保留期配置不等于物理清理能力已验收；清理验证前不导入业务或评测正文。Langfuse 不替代现有 PG 权威记录或冻结验收。

本镜像实测未将初始化的30天目标写入项目保留期；LF-3须实现并验证清理后才能启用业务采集，不能依靠这个参数宣称已完成自动删除。

网关使用独立入口网以支持 Docker Desktop 回环访问，Web和其他评测组件仅连接内部网络。已关闭平台遥测和内置 Agent；本机入口网实测仍具公网 TCP 能力，不能将网络配置称为完全断网。供应商凭据不传入本栈。

LF-2提供结束节点的元数据投影：从PG读取阶段/Agent事实并逐条关联`call_meter`，独立有界线程发送，保留取消、UNKNOWN和Token预占，不导出正文或按未知价格估价。64位节点ID以PG映射表持久化，碰撞重试、重启复用；HTTP接收不等于质量通过。仅结束节点进入平台，未结束节点不伪造完成时间。

`./scripts/verify-local.ps1 -Scope Langfuse`验证受影响的PG/导出器/架构；`./scripts/langfuse-local.ps1 -Action VerifyMetadata`额外启用本机平台合成入库查询，仍不调用真实模型。正常`local`配置不创建导出器；只有同时使用`local`与`langfuse-validation` profile、明确指定未过期的`lf2_test_`合成用户才装配。合成批次起点来自用户创建时间，重启不刷新；同批须复用原`LF_SALT`。生产采集仍须等待LF-3清理治理验收，不把验证profile用于真实账号。

### 评分与保留台账基础（LF-3a）

`LangfusePilotSuite`只加载P01/P02/R01/R02/R03固定合成资源，输入与裁判分离；`EvaluationScorecard`分别计算程序门禁、四项人工评分和任务完成状态。未运行不填分、未评审保持待评，不跨执行模式统计。人工回执须绑定原始运行与全轮执行证据；协议本身不认证人工身份，也不提供评分写入口。

`EvaluationRetentionService`和V40台账使用PG时间检查原始开始后720小时到期；幂等登记不修改归属、时间或配置，主动撤销保留标记，迟到副本增加清理代次。清理期限固定为首次阻断后24小时。台账回执只记录清理适配器的声明，不等于物理删除证明。

`./scripts/verify-local.ps1 -Scope LangfuseRetention`验证上述协议及真实本机PG的归属、期限、回滚和撤销竞争，不调用模型。LF-3a只交付台账；下述LF-3b-1追加入口屏障，平台数据集/分数发布与物理清理仍未完成，生产采集及评测全文上传继续关闭。

### 平台访问屏障（LF-3b-1）

3100端口由网关提供，原始Web不发布宿主端口。网关在请求前、读完请求后、返回上游正文前查询PG控制服务；未核验、到期、撤销或依赖不可用时拒绝访问。响应禁止缓存，转发并发与请求/响应大小均有上限。`/_gateway/health`只表示网关进程存活，不表示平台可访问或治理已通过。

治理专用`local,langfuse-governance` profile提供8093控制端口，使用本机随机`LF_GATE_TOKEN`；重启先关闭旧资格。普通local不监听该端口。V41默认关闭资格，本次没有开放接口，不能手动置true冒充完成副本核验。平台所有记录共用入口，任一到期/撤销记录会使整站拒绝访问，后续须在清理核验后处理阻断项。

`./scripts/verify-local.ps1 -Scope LangfuseAccess`检查真实PG和控制HTTP；`./scripts/langfuse-local.ps1 -Action VerifyAccess`在固定镜像中运行网关测试，并验证实际Docker到宿主控制端口在拒绝、异常及关闭三种情况下仍封闭入口。测试不开放真实数据，不调用模型。

本步完成入口隔离，没有完成数据集/评分发布、清理器、平台存储/缓存/备份物理删除或恢复标记校验，LF-3整体尚未验收；生产及评测全文上传继续关闭。

### 评分证据与私有复核后端（LF-3b-2中的评分步骤）

V42保存不可变程序来源和追加的人工评分记录，均关联原run。来源只能由可信执行器内部登记，HTTP不提供上传程序成绩的入口；当前尚未将现有真实评测执行器自动接到登记方法。原开始时间、数据/配置指纹必须匹配保留台账，重试和评分不延长到期时间。

仅`local,langfuse-scoring-validation` profile装配验证用复核接口：`GET/POST /api/v1/evaluations/{run}/review`。沿用登录会话和CSRF；只允许复核本人活跃运行，提交需包含明确确认、四项0～2分、证据指纹、预期评分修订和幂等请求ID。评分依据采用结构化枚举，不接收自由文本、程序结论或userId。未运行不能评分，程序失败不能由人工高分抵消；旧请求重放不恢复旧评分指针。

接口只返回元数据和评分状态，尚无完整执行材料阅读或评分前端；不得仅依据该摘要进行正式质量复核。当前测试评分均为合成夹具，未转换历史人工确认，不代表用户已给出四项分数。普通local不启用此接口。

`./scripts/verify-local.ps1 -Scope LangfuseScoring`覆盖真实PG事务/并发、Redis登录及本机HTTP权限、评分规则和相关认证回归。平台数据集/分数发布、全副本清理、独立删除标记恢复核验仍未完成；Langfuse入口继续503，不修改核验标志以开放页面。

### 数据集协议与PG历史版本清理

`./scripts/langfuse-local.ps1 -Action VerifyDataset`验证本机固定镜像中的数据集协议。它只创建随机`ta-protocol-*`数据集，五个条目仅含用例ID和数字协议标记，不上传冻结场景正文、用户资料或模型输出。认证留在容器内存，普通宿主入口保持关闭；这是一项受控维护检查，不绕过闸门继续旧的链路写入探针。

适配器校验项目、原始时间和托管标记；同名来源不匹配时拒绝覆盖。HTTP有次数/大小/超时上限，写入未知结果不自动重发。复查不存在使用纯GET，不能调用创建操作导致目标复活。

本版本公开API没有数据集删除接口，原生条目删除会保留历史和空删除标记。清理适配在固定schema下锁定精确数据集，验证所有版本均为本工具的数字探针，再通过原生PG级联删除整个范围并复查PG及API。存在正文、其他配置、源轨迹、媒体或实验引用时拒删；不会清理其他项目或未确认范围。中途退出留下的协议探针可由其PG标记找回，校验失败保留待核对，不静默丢弃。

维护脚本复用固定镜像已带的Node/Prisma，不增加业务调度器或修改第三方表结构。当前只验证协议数据集图，正式样本发布、评分/轨迹投递及ClickHouse/S3/Redis/备份等跨存储清理仍未接通，不能据此宣称全副本清理或LF-3整体验收完成。
